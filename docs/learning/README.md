# Learning Inbox

Provisional lessons from completed work, before they become durable memory.

- Prefer EXECUTABLE memory over prose: a regression test, a lint/Semgrep rule, a schema constraint, a CI gate. A lesson that can run never rots.
- A proposal needs: observation, evidence (link the PR/incident), root cause, the reusable rule, scope, and a review date.
- Do not persist: one-off observations, speculation, workarounds for defective code, personal preference, or anything already documented.
- Nothing here is binding until reviewed and promoted - into a test, a doc section, or (rarely, founder-approved) CLAUDE.md.
- Never store secrets, credentials, or personal data here.
