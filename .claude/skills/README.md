# Design & FE Skill Kit

Craft skills for the design and frontend lanes. They load on demand (Claude Code picks them up from this directory); they are part of the DEFAULT web stack layer - review them if the project is not web-based.

## Routing

| Skill | Primary user | For |
|---|---|---|
| hallmark | Reem | Greenfield pages, design audits, redesigns, DNA extraction from references |
| frontend-design | Reem | Aesthetic direction for new interfaces |
| emil-design-eng | Reem / Yousef | Polish philosophy, component feel, animation decisions |
| better-layout | Reem / Yousef | Layout structure, spacing, grouping, RTL/logical properties |
| apple-design | Yousef | Fluid motion: springs, gestures, drag/sheet interactions |
| design-motion-principles | Yousef | Building motion + auditing AI-slop animation |
| find-animation-opportunities | Yousef | Read-only sweep for missing (and unwanted) motion |
| animation-vocabulary | anyone | Naming a motion effect precisely |
| break-ui | Dana | Adversarial worst-case-data stress tests of components |

## Precedence (read first)

The PROJECT DESIGN SYSTEM ALWAYS WINS. Once a project has tokens, brand guidelines, or a Figma source of truth, these skills operate INSIDE it: layout, motion, and polish guidance applies; aesthetic invention (new palettes, new type pairings, new themes) does not. Bold-direction skills (hallmark, frontend-design) are for greenfield work, marketing surfaces, or when Reem is creating the design system itself. "Real brand artwork only" style rules in a project outrank anything here (rule precedence: dev-guidelines.md).
